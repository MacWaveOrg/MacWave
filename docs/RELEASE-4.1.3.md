# MacWave 4.1.3 发布说明

> 本文说明 4.1.3 的变更范围与升级方式。
> 这是一个**修复版本**，没有新功能，不改数据格式，升级无迁移步骤。
>
> 发布分支：`4.1`

---

## 概述

4.1.0 → 4.1.1 的自更新会**报告成功，但并没有装全**。

这不是「多打了几行红字」的观感问题：从这一版起，只要有一个文件没下到，
升级脚本会告诉你失败了、安装目录不会被标记成新版本。上一版是反过来的 ——
终端里刷过一串 `404`，最后照样打印 `MacWave has been updated to 4.1.1!`。

| 问题 | 4.1.1 | 4.1.3 |
| --- | --- | --- |
| 清单里混进不存在的路径 | 有（两个 `__pycache__`） | 已过滤 |
| 某个文件下载失败 | **静默跳过，报成功** | 整次更新失败，不写版本号 |
| 文件下到了但没能就位 | 静默跳过 | 整次更新失败 |
| 装好但没加可执行位 | 静默跳过 | 整次更新失败 |
| 报错里的镜像密码 | **明文打印** | 打码 |
| 「变更清单」为空 | 静默「成功」，什么都没换 | 生成阶段就拒绝 |

---

## 已经升过 4.1.1 的人需要做什么

**不需要重装，但值得核对一次。** 那次升级实际漏掉的是两个 `__pycache__`
目录 —— Python 会自己重建，没有影响；被顺带覆盖的 `lib/install.sh`、
`lib/uninstall.sh` 与分支上的字节相同，也没有影响。

所以已经升到 4.1.1 的机器是好的。真正危险的是这个机制：同样的情况若发生在一个
真正的代码文件上，4.1.1 也会说「成功」。4.1.3 修的就是这一点。

想确认安装完整，两条命令：

```bash
wave -V                      # 应打印 4.1.3（升级后）
wave list --all              # 已装的包还在，版本号正常
```

## 修了什么

### 1. 升级清单不再包含 `__pycache__`

`Selfupdate/macwavedata/4.1.1/update_commands.sh` 里出现过四条本不该有的路径：

```
pkg/__pycache__          ← 目录，git 里根本不存在
surfboard/__pycache__    ← 同上
lib/install.sh           ← 本该被排除
lib/uninstall.sh         ← 同上
```

来源是**发版命令本身**。检查清单第 4 步原本写的是：

```bash
--files lib/*.py lib/*.sh pkg/* surfboard/*
```

shell 通配符在真实工作区里会展开出上面那四条。而生成器里的过滤器只写在「从 git
读文件树」那条路上，`--files` 是另一条入口，压根没经过。

现在过滤统一放在 `sanitize()` 里，不管清单来自哪儿都要过；被丢掉的条目会打印
出来（清单少一行没人知道）。`--delta` 过滤后为空也会拒绝生成 —— 一条
`want` 都没有的升级脚本会瞬间「成功」返回，等于什么都没换，连报错都没有。

### 2. 任何一步失败都会让整次升级失败

升级脚本里的 `want` 失败后只 `return 1`，而调用它的是几十行裸的 `want ...`，
脚本没有 `set -e`，调用方也不看返回值 —— 错误被下一行覆盖掉了。

改成 `exit 1`。同一类的还有两处：

```bash
run mv -f "$partial" "$destination"     # 权限不足时文件还留在 .macwave-part 里
run chmod +x "$destination"             # 装好了但命令跑不起来 → command not found
```

后者尤其值得说：用户看到的会是「命令不存在」，几乎不可能联想到是升级时权限不够。

### 3. 报错里的地址打码

用镜像时地址形如 `https://用户:密码@mirror/...`。上一版在下载失败时把它原样
打印，等于把密码写进终端滚屏、CI 日志和求助截图。

现在输出 `https://用户:***@mirror/...`。只在 `//` 之后、第一个 `/` 之前找 `@` ——
路径里的 `@` 是合法文件名（`jq@1.8.2.arm64`），拿整条串找会把包名当成密码位置。

### 4. 测试脚本里的 locale 依赖

新加的回归脚本里有一行 `（退出码 $rc）`。在 UTF-8 locale 下，bash 3.2 会把紧跟
变量名的全角括号当成名字的一部分，于是去找一个叫 `rc）` 的变量 —— CI 上直接
`unbound variable`，而本机 locale 是 C、按字节处理，一直是绿的。

本仓库同类写法另有四处，一并改了。这类问题的特征是**报错完全指不到真问题**。

## 升级方式

```bash
wave selfupdate
```

4.x 内部升级，无迁移步骤，不改数据格式，不需要 sudo。

**3.x 用户不走这条路。** 跨大版本守卫内置于 3.x 脚本，你会看到：

```
🌊 MacWave 4 is a new major version, so it cannot be installed with selfupdate.
🌊 Your version: 3.2.x. Please install 4.1.3 from the website:
   https://macwave.org
🌊 Your current installation has not been changed.
```

请按提示从官网安装。4.0 的迁移说明见 [RELEASE-4.0.0.md](./RELEASE-4.0.0.md)。

## 已知限制

- 升级仍是「整文件替换」，没有回滚。某一步失败时安装目录可能处于新旧混合的
  状态，但因为**不写 `VERSION.json`**，重跑 `wave selfupdate` 会从头再来一遍，
  而所有步骤都是幂等的，所以能自愈。
- 清单过滤只覆盖 `lib`、`pkg`、`surfboard` 三个目录。将来新增安装目录要一起
  改 `INSTALLED_DIRS`，否则整个目录会被当成「不在安装范围」过滤掉。
- `redact_url` 只处理 URL 里的 userinfo。如果哪天密码出现在别的位置（比如
  自定义请求头），它不会打码。

## 本版随附的数据

无数据格式变更。

```
macwavedata/latest.toml                  哪个版本是最新的
macwavedata/4.1.3/update_commands.sh     这一版具体怎么装
```

`update_commands.sh` 按版本冻结，发布后不再修改。

> 例外：4.1.1 的 `update_commands.sh` 在 4.1.3 发布时被重发过一次 ——
> 那份清单里的脏条目会让所有从 4.1.0 升上来的人踩到。改代码只保护下一个版本，
> 改数据才能保护这一个版本。
