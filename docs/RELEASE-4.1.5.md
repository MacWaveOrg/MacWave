# MacWave 4.1.5 发布说明

> 本文说明 4.1.5 的变更范围与升级方式。
> 这是一个**功能修正版本**：补齐三档超时中的两档（连接与读数据），并修掉三处
> 「旗标被解析、却没有作用于请求」的缺陷。`--skip-ssl` 的作用范围同时扩展到全部请求。
> 数据格式无变化，升级无迁移步骤。
>
> 发布分支：`4.1`

---

## 概述

`--connect-timeout` 与 `--content-time` 早已出现在帮助里，但在 4.1.4 上它们只在
一部分请求上生效，在最靠前的那个请求上则完全无效 —— 而那恰恰是最容易卡住的一个。
本版把两档超时真正接到每一条出网路径上，并顺带修正了同源的 `--skip-ssl`。

| 你想要的 | 现在可以这样写 | 4.1.4 上 |
| --- | --- | --- |
| 握手超过 3 秒就放弃 | `wave install jq --connect-timeout=3s` | 版本清单仍等 30 秒 |
| 连上后 5 秒没数据就放弃 | `wave install jq --content-time=5s` | 依赖元数据不认这一档 |
| 自更新时同样限制握手 | `wave selfupdate --connect-timeout=3s` | 静默忽略，连非法值也不报错 |
| 对自签证书的镜像跳过校验 | `wave install jq --skip-ssl` | 第 4 步即因证书校验失败 |

---

## 一、三档超时

三者分工不同，`requests` 的 `timeout` 参数本身只表达前两项：

| 旗标 | 管什么 | curl 中的对应写法 |
| --- | --- | --- |
| `--connect-timeout` | TCP/TLS 握手多久算失败 | `--connect-timeout N` |
| `--content-time` | 连上之后多久收不到数据算失败 | `--speed-limit 1 --speed-time N` |
| `--max-time` | 整次操作的总额 | `--max-time N` |

### 默认值

一个都不给时行为与 4.1.4 一致：

| 项 | 默认 |
| --- | --- |
| 连接 | 10 秒 |
| 读数据 | 30 秒 |
| 总额 | 30 秒 |

单独给 `--content-time` 且大于 30 秒时，总额自动抬高到该值；否则用户显式放宽的
读数据时限会被默认的总额悄悄压回去，等于没写。`--connect-timeout` 不参与这一抬高：
默认的 10 加 30 会把总额撑到 40 秒，从而改变「默认 30 秒」这个既有行为。

### 取值写法

与 curl 一致：纯数字按秒计，也接受 `40s`、`1min`、`1min20s`、`2h`、`250ms`。
`--content-time=1min` 与 `--content-time 1min` 两种写法等价。取值不合法时立即报错并
退出，不会带着默认值继续。

```bash
wave install jq --connect-timeout=3s --content-time=5s --max-time=10min
wave latest --all --max-time=2min
```

## 二、修掉的三处「解析了但没有生效」

三处缺陷同源：旗标在入口被正确解析，但值没有传到真正发请求的那一层。

| # | 位置 | 4.1.4 的表现 | 本版 |
| --- | --- | --- | --- |
| 1 | `wave install` 的版本清单请求 | 使用固定的 30 秒，三档全部无效 | 使用命令行给出的三档 |
| 2 | 依赖元数据请求 | 只认 `--max-time`，另两档被丢弃 | 三档都生效 |
| 3 | `wave selfupdate` | 完全不解析这两档，非法值也不报错 | Python 与 Shell 两层都解析 |

第 3 处涉及两层：`lib/selfupdate.py` 负责取版本数据，`lib/selfupdate.sh` 负责下载文件。
两层的取值规则都来自 `lib/timeouts.py`，命令行文本原样下传，中间任何一层都不替对方
算好，因此不存在两套解析结果不一致的可能。

同时修掉 `wave upgrade --all` 取索引名字清单时同样使用固定超时的问题。

---

## 三、`--skip-ssl` 现在作用于全部请求

4.1.4 及更早，该旗标只在包体下载那一步生效。其余请求（版本清单、`@common`、
版本记录、依赖元数据、`info`、`search`、`latest`、`selfupdate`）仍校验证书 ——
而自签证书或企业代理签发的镜像，恰好在**第一个**请求上就会失败，旗标等于没写。

本版把开关收敛到单一模块 `lib/tls.py`，所有出网路径共用它。

安全语义没有放松：

| 情形 | 结果 |
| --- | --- |
| 不带旗标 | 照常校验证书 |
| `--skip-ssl` 并回答 `y` | 本条命令的全部请求不再校验 |
| `--skip-ssl` 但回答 `n` | 照常校验证书 |
| 非交互（stdin 为空） | 按拒绝处理，照常校验证书 |
| `--skip-ssl` 且带 `-s` | 不提问，直接生效（与 `-X` 同一条原则：写出来就是用户的意思） |

`wave upgrade --all` 只询问一次，不会为每个包各问一遍。

## 兼容性

- 不设任何超时旗标时，行为与 4.1.4 完全一致。
- `--skip-ssl` 的作用范围扩大是**安全相关的行为变更**：此前在部分请求上会失败的命令，
  本版会成功。仍然需要用户显式确认，不会默认关闭校验。
- 不涉及数据格式变更，无需迁移。

---

## 升级方式

```bash
wave selfupdate
```

4.x 内部升级，无迁移步骤，不改数据格式，不需要 sudo。

本版新增一个程序文件 `lib/tls.py`，它已包含在本版的 `update_commands.sh` 中；
若该文件缺失，所有命令都会在导入阶段失败，因此请勿手工裁剪该清单。

---

## 已知限制

- 版本数据的取值在**未给任何一档超时**时优先走标准库（`urllib`），该路径只有一个
  socket 超时，无法区分连接与读数据。给了任意一档时改用 `curl`，三档各自独立。
- `--skip-ssl` 需要交互确认。脚本中若确实需要跳过校验，请在同一条命令上带 `-s`，
  或通过管道显式回答 `y`；否则按拒绝处理。
- 超时只作用于单次请求，不改变重试次数。依赖元数据与自更新脚本仍各自按原策略重试。
